========================================================
INSTAGRAM AUR MESSENGER INTEGRATION — CHALLENGES AUR SOLUTIONS
(Roman Urdu)
========================================================

Ye file is liye likhi gayi hai ke jab bhi koi naya banda (ya hum khud
kabhi bhool jayein) Instagram ya Messenger dobara connect kare, to use
pata ho ke kaunse masle aaye thay, kyun aaye thay, aur kaise theek
huye. Har cheez aasan zaban mein likhi hai, taake koi bhi parh ke
samajh sake — chahe wo developer ho ya na ho.

Neeche pehle Instagram ke challenges hain, phir Messenger ke, phir
dono mein common cheezein, aur sab se aakhir mein saari zaroori
PERMISSIONS ki poori list hai.

========================================================
HISSA 1: INSTAGRAM KE CHALLENGES
========================================================

--------------------------------------------------------
Challenge 1: Webhook "verified" ho gaya lekin real message nahi aa raha
--------------------------------------------------------
Kya hua tha:
Meta Dashboard mein webhook Callback URL save kiya, "Verify and save"
click kiya, aur wo successfully verify bhi ho gaya (green tick). Lekin
jab real Instagram se DM bheja gaya, hamare server tak koi request
hi nahi pohanchi — na success na fail, bilkul kuch nahi.

Kyun hua:
Meta ka webhook "verify" hona sirf itna batata hai ke aapka URL sahi
hai aur token match ho raha hai. Ye is baat ki guarantee nahi deta ke
real messages bhi aayenge. Jab tak app "Development Mode" mein hai,
Meta Instagram messaging events (real DMs) bilkul deliver nahi karta —
chahe sab kuch dashboard mein sahi kyun na laga ho.

Solution:
App ko Meta Dashboard mein "Publish" karna para (In Development se
Live/Published state mein le kar jana). Publish karne se pehle ye
cheezein zaroori theen:
  - App Icon (1024x1024 image)
  - Privacy Policy URL
  - Terms of Service URL
  - Data Deletion Instructions URL
  - Category select karna
Ye saari cheezein humne apni site par hi banayi (src/public/
privacy-policy.html, terms-of-service.html, data-deletion.html) aur
index.js mein routes bana kar Meta Dashboard mein daal diye.

--------------------------------------------------------
Challenge 2: Do alag "API setup" wizards ka confusion
--------------------------------------------------------
Kya hua tha:
Meta Dashboard mein Instagram ke liye DO alag raste hote hain:
  1) "API setup with Facebook login" — purana, Facebook Page ke
     zariye Instagram connect karne wala tareeqa.
  2) "API setup with Instagram login" — naya, seedha Instagram
     account se login karne wala tareeqa.
Humne shuru mein sirf pehle wale (Facebook login) se account connect
kiya. Har cheez dashboard mein sahi lag rahi thi (Page subscribe tha,
webhook fields subscribe thay, app Publish tha) — phir bhi real
messages hamesha "missing" reh jate thay.

Kyun hua:
In dono raaston ki apni alag webhook configuration hoti hai. Sirf ek
jagah Callback URL update karna kaafi nahi — dono jagah (dono
use-cases ke "Configure webhooks" section mein) sahi Callback URL aur
verify token set hona chahiye, warna sirf ek pipeline kaam karega.

Solution:
Humne dono jagah Callback URL ko ek hi shared URL par set kiya:
  https://<your-domain>/api/v1/meta/webhook
Aur end mein pata chala ke "API setup with Instagram login" wala
tareeqa zyada reliable tha is specific setup ke liye — is liye hum ne
usi ko use karna shuru kiya (neeche Challenge 5 mein detail hai).

--------------------------------------------------------
Challenge 3: Tester invite accept nahi hua tha
--------------------------------------------------------
Kya hua tha:
Jis Instagram account se hum test kar rahe thay (customer wala
account), use App Roles mein "Instagram Tester" add kiya — lekin phir
bhi kuch farq nahi para.

Kyun hua:
Sirf "Add" karna kaafi nahi hota. Us Instagram account ko khud jaake
apne Instagram app mein "Settings > Apps and Websites > Tester
Invites" mein ja kar invite ACCEPT karni parti hai. Jab tak accept na
ho, wo account "pending" reh jata hai aur uske messages count nahi
hote.

Solution:
Tester account se invite accept ki, phir cheezein aage barhi.

--------------------------------------------------------
Challenge 4: subscribed_fields mein ghalat field ka naam
--------------------------------------------------------
Kya hua tha:
Jab humne app ko Page se subscribe karne ki API call ki
(POST /{page-id}/subscribed_apps), Meta ne ye error diya:
  "Param subscribed_fields[3] must be one of {...} — got messaging_seen"

Kyun hua:
"messaging_seen" naam ka field ab valid nahi hai. Naye Graph API
version mein iski jagah "message_reads" use hota hai.

Solution:
Code mein subscribed_fields ko change kiya:
  Pehle: messages, messaging_postbacks, message_reactions, messaging_seen
  Ab:    messages, messaging_postbacks, message_reactions, message_reads

--------------------------------------------------------
Challenge 5: SAB SE BARA CHALLENGE — Ek account ki DO alag IDs
--------------------------------------------------------
Kya hua tha:
Sab kuch (Page subscription, webhook fields, Publish, Tester) sahi
hone ke bawajood, real DM aane par hamara code use "No active tenant"
keh kar reject/skip kar deta tha. Bohot der tak samajh nahi aaya ke
masla kahan hai, kyunke dashboard mein har cheez "sahi" dikhti thi.

Kyun hua (asal wajah):
Instagram ek hi account ke liye ALAG ALAG numeric IDs deta hai,
depending on ke aap kis tareeqe se us account tak pohanche hain:

  1) "ig_user_id" (Classic ID) — jab aap Facebook Page ke zariye
     account connect karte hain (GET /page-id?fields=
     instagram_business_account). Ye ID sirf message BHEJNE ke liye
     kaam aati hai (POST /{ig_user_id}/messages).

  2) "ig_scoped_id" (Messaging-scoped ID) — jab koi real Instagram DM
     aata hai, Meta apne webhook mein isi ID ko sender/recipient ke
     taur par bhejta hai. Ye ID (1) wali se BILKUL alag number hoti
     hai, magar hoti usi account ki hai.

Hamara code sirf (1) wali classic ig_user_id ko match kar raha tha,
jabke real webhook events hamesha (2) wali scoped ID bhejte thay. Is
liye match kabhi hota hi nahi tha aur message hamesha "skip" ho jata
tha.

Kaise pata chala:
Humne khud se manually ek reverse test kiya — apne connected account
(devnouman44) se doosre test account (nouman123444) ko message bheja.
Us se aane wala webhook event genuine tha (is_echo nahi tha), aur
usme devnouman44 ki ID "1767391427788536" thi — jo hamare database mein
save ig_user_id (17841437913367528) se bilkul mukhtalif thi. Isi se
confirm hua ke ye do alag IDs hain.

Solution:
  1) Database (instagram_details table) mein ek naya column banaya:
     "ig_scoped_id" — taake dono IDs alag alag save ho sakein.
  2) Webhook match karne wale code (processWebhookEvent) ko update
     kiya ke wo ig_user_id AUR ig_scoped_id — dono mein se kisi se
     bhi match kare.
  3) Jo scoped ID humne discover ki, wo manually database mein save
     ki.
  4) Naye connect hone wale accounts ke liye bhi rasta banaya: jab
     tak unki scoped ID pehli baar kisi real message se pata na
     chale, tab tak "No active tenant" ka warning aayega jisme scoped
     id bhi dikhai degi — wahan se admin PUT /api/v1/instagram/account
     API se ig_scoped_id manually set kar sakta hai.

--------------------------------------------------------
Challenge 6: Message SEND karna kaam nahi kar raha tha
--------------------------------------------------------
Kya hua tha:
Inbound (receive) theek ho gaya, lekin jab reply bhejne ki koshish ki
to Meta ne ye error diya:
  "(#3) Application does not have the capability to make this API call."

Kyun hua:
Jo purana Page Access Token (Facebook Login wale tareeqe se mila tha)
save tha, wo Instagram messaging ke liye poori tarah authorize nahi
tha. Jab humne "API setup with Instagram login" ke zariye ek naya
token banaya (jo "IGAA..." se shuru hota hai — Instagram ka apna token
type), to pata chala ke Instagram Login ke tareeqe mein:
  - API ka host bhi alag hai: graph.instagram.com
    (graph.facebook.com nahi)
  - Recipient (jise message bhej rahe hain) ki ID bhi TEESRI alag ID
    hai — jo sirf GET /{ig-id}/conversations wale endpoint se milti
    hai, webhook wali scoped ID se bhi mukhtalif.

Yani ek hi Instagram account ke liye humne total TEEN alag IDs dekhi:
  a) Classic ig_user_id           -> Page-linking / management ke liye
  b) Messaging-scoped ID          -> webhook events mein
  c) Conversation-scoped ID       -> graph.instagram.com se send karne
                                      ke liye recipient id

Solution:
  - Sending ke liye graph.instagram.com host use karna shuru kiya.
  - Naya IGAA-type token use kiya (purane Page token ki jagah).
  - Recipient ki sahi ID GET /{ig-id}/conversations API se nikali
    (participants list mein milti hai), aur usay message bhejte waqt
    use kiya.
Is se sending successfully kaam karne lagi.

--------------------------------------------------------
Challenge 7: Purana token mein permission missing thi
--------------------------------------------------------
Kya hua tha:
Token check karne par ye error mila:
  "requires the 'pages_read_engagement' permission..."
Jabke dashboard mein ye permission "Ready for testing" dikha rahi thi.

Kyun hua:
Jab koi naya permission app mein add ki jati hai, wo sirf AAGE se
banne wale tokens mein shamil hoti hai. Jo token pehle se ban chuka
tha (permission add hone se PEHLE), usme wo permission nahi hoti —
chahe dashboard ab kuch bhi dikhaye.

Solution:
Account ko dobara "Reconnect with Facebook" kar ke naya token banaya,
taake sab current permissions naye token mein shamil ho jayein.

========================================================
HISSA 2: MESSENGER KE CHALLENGES
========================================================

--------------------------------------------------------
Challenge 1: Webhook fields subscribe hi nahi thay
--------------------------------------------------------
Kya hua tha:
Page connect ho gaya, subscribed_apps bhi Meta ki taraf se "active"
dikha raha tha, Callback URL bhi sahi tha — phir bhi koi request
hamare server tak nahi pohanch rahi thi.

Kyun hua:
"Messenger API Settings" ke "Configure webhooks" section mein niche
scroll kar ke dekhne par pata chala ke "Webhook fields" list mein
KOI bhi field Subscribe nahi thi (sab "Unsubscribed" the) — na
"messages", na kuch aur. Sirf Callback URL sahi hona kaafi nahi hota,
har field ka apna alag "Subscribe" toggle ON karna parta hai.

Solution:
In fields ko Subscribe kiya (jo hamara code actually handle karta
hai):
  - messages              (zaroori — text/media messages ke liye)
  - messaging_postbacks    (button clicks ke liye)
  - message_deliveries     (delivery receipt ke liye)
  - message_reads          (read receipt ke liye)

--------------------------------------------------------
Challenge 2: Test karte waqt ghalat direction mein message bheja
--------------------------------------------------------
Kya hua tha:
Page ke apne inbox se customer ko message bheja aur wait kiya ke
webhook aaye — lekin kuch nahi aaya.

Kyun hua:
Webhook sirf tab fire hota hai jab CUSTOMER Page ko message kare, na
ke jab Page khud kisi ko message bheje. Page apna khud ka message
bhejta hai to wo "outbound" hota hai, jiski hamein zaroorat nahi
webhook receive karne ke liye.

Solution:
Do alag Facebook accounts use kiye:
  - Ek account jo Page ka Admin/Owner hai (Page connect karne ke liye)
  - Ek bilkul ALAG, doosra Facebook account jo "customer" ban kar
    Page ko message kare
Customer wale account se Page ko message bhejne par webhook sahi se
fire hua.

--------------------------------------------------------
Challenge 3: ngrok tunnel "reconnecting" ho jana
--------------------------------------------------------
Kya hua tha:
Kai baar aisa hua ke sab kuch sahi set hone ke bawajood, ngrok
Inspector mein koi request hi nahi dikhti thi — bilkul empty.

Kyun hua:
ngrok Inspector ke top par status "reconnecting" dikha raha hota tha,
matlab tunnel khud hi is waqt down/unstable tha, ya phir local
`npm run dev` server band ho chuka tha. Jab tunnel ya server hi down
ho, to Meta ki request kahin nahi jaati.

Solution:
Har baar test karne se pehle check karna:
  1) `npm run dev` terminal chal raha hai aur "SMM App is listening"
     dikha raha hai.
  2) ngrok Inspector (127.0.0.1:4040) ka status "online" hai (hara
     rang), "reconnecting" nahi.

========================================================
HISSA 3: DONO KE LIYE COMMON LESSONS
========================================================

1) Ek shared webhook endpoint banaya:
   Instagram aur Messenger — dono ke liye ek hi URL:
       /api/v1/meta/webhook
   (WhatsApp ka apna alag webhook raha, use nahi chheda gaya.)
   Ye is liye kiya taake Meta Dashboard mein har jagah alag alag URL
   manage na karna paray — sirf ek Callback URL, ek Verify Token.

2) Realtime (live) updates missing thay:
   Jab bhi koi naya message aata ya jata tha, chat inbox page (UI)
   khud-b-khud update nahi hoti thi jab tak page refresh na kiya
   jaye. Wajah ye thi ke Socket.IO events (message:inbound,
   message:outbound, message:status) code mein bilkul likhe hi nahi
   gaye thay Instagram aur Messenger ke liye (WhatsApp mein pehle se
   thay). Ye add kiye gaye taake inbox live update ho.

3) Har naye connect kiye gaye account ko turant "kaam kar raha hai"
   maan kar mat chalein — hamesha ek real test message bhej kar
   confirm karna chahiye, kyunke dashboard mein "sab sahi" dikhna aur
   waqai kaam karna do alag cheezein nikli hain.

========================================================
HISSA 4: MESSAGING KE LIYE ZAROORI PERMISSIONS (POORI LIST)
========================================================

Ye permissions "Facebook Login for Business" configuration mein
add honi chahiye (App Dashboard > Facebook Login for Business >
Configurations), taake connect/embedded-signup ka popup inhe
grant kar sake:

--- Instagram messaging ke liye ---
  - instagram_basic              -> account ki basic info (profile,
                                     media) parhne ke liye
  - instagram_manage_messages    -> Direct messages bhejne/parhne
                                     ke liye (SABSE ZAROORI)
  - instagram_manage_comments    -> comments manage karne ke liye
                                     (optional, agar comments bhi
                                     chahiye)
  - instagram_content_publish    -> Instagram par post/content
                                     publish karne ke liye (optional)

--- Facebook Page / Messenger ke liye ---
  - pages_show_list              -> user ke Pages ki list dekhne
                                     ke liye (SABSE ZAROORI)
  - pages_messaging               -> Page se Messenger messages
                                     bhejne/parhne ke liye
                                     (SABSE ZAROORI)
  - pages_read_engagement         -> Page ki info (name, details)
                                     parhne ke liye
  - pages_manage_metadata         -> Page ko app se subscribe karne
                                     ke liye (webhook ke liye zaroori)

--- WhatsApp ke liye (agar WhatsApp bhi connect karna ho) ---
  - whatsapp_business_management -> WhatsApp Business Account
                                     manage karne ke liye
  - whatsapp_business_messaging  -> WhatsApp messages bhejne/parhne
                                     ke liye

--- General / Business ke liye ---
  - business_management          -> Business Manager/Portfolio ki
                                     assets access karne ke liye
  - email                        -> login karne wale user ki email
                                     (optional, sirf identify karne
                                     ke liye)

NOTE: Sirf permission add karna kaafi nahi — token BANNE ke waqt wo
permission maujood honi chahiye. Agar baad mein koi permission add
ki jaye, to pehle se connected accounts ko RECONNECT karna zaroori
hai, warna purana token naye permission ke bina hi rahega
(Challenge 7 dekhein).

--------------------------------------------------------
WEBHOOK "SUBSCRIBED FIELDS" KI LIST (Permissions se ALAG cheez)
--------------------------------------------------------
Ye upar wali OAuth permissions se bilkul mukhtalif cheez hai. Ye
Meta App Dashboard ke "Webhooks" section mein, har Page ke liye
alag se Subscribe karni parti hain (POST /{page-id}/subscribed_apps
ke zariye code khud kar deta hai, magar App-level webhook config mein
bhi field ka apna Subscribe toggle ON hona chahiye):

  - messages              -> naya text/media message aane par
  - messaging_postbacks    -> button/quick-reply click hone par
  - message_reactions      -> kisi message par reaction lagne par
  - message_reads          -> message "read" (parh liya) hone par
  - message_deliveries     -> message "deliver" hone par

Instagram aur Messenger dono ke liye ye fields alag alag jagah
subscribe karni parti hain (dono "use cases" ke apne apne
"Configure webhooks" section mein) — sirf ek jagah karna kaafi
nahi.

========================================================
AAKHRI CHECKLIST — NAYA ACCOUNT CONNECT KARTE WAQT
========================================================
1. App Publish hai? (Development mode mein real messages nahi aate)
2. Facebook Login Configuration mein saari permissions upar wali
   list ke mutabiq add hain?
3. Account connect/reconnect us WAQT kiya jab saari permissions
   already add thi (naya token banane ke liye)?
4. Page/Account "subscribed_apps" mein hamari app dikha rahi hai?
   (GET /{id}/subscribed_apps se check karein)
5. App-level Webhooks config mein "messages" field Subscribed hai?
   (dono Instagram aur Messenger use-cases mein alag check karein)
6. Callback URL sab jagah ek hi hai:
   https://<your-domain>/api/v1/meta/webhook
7. Test karte waqt do ALAG Facebook/Instagram accounts use kiye —
   ek Page/account ka owner, doosra "customer" ban kar message
   bhejne wala?
8. `npm run dev` chal raha hai aur ngrok "online" hai (reconnecting
   nahi)?
9. Real message bhej kar terminal/ngrok Inspector mein
   POST /api/v1/meta/webhook dekha?

Agar in sab ka jawab "haan" hai, to message aana chahiye. Agar phir
bhi na aaye, to sabse pehle ye check karein ke webhook payload mein
jo ID aa rahi hai, wo hamare database ki ig_user_id/ig_scoped_id se
match kar rahi hai ya nahi (Challenge 5 wala masla dobara ho sakta
hai naye accounts ke saath).
